How it works

An offline pipeline (Spark → TensorFlow → FAISS → Redis, scheduled by Airflow) feeds an online FastAPI service.

Online request path

GET /recommend/{customer_id}
1 · Feature storeProfile + purchase features read from Redis (sub-millisecond).
→
2 · Query towerTensorFlow network: customer + month + day of week → 64-d vector.
→
3 · ANN searchFAISS HNSW over pre-computed article vectors (cosine similarity).
→
4 · EnrichArticle details from Redis. Unknown visitors get trending items.
WEEK 1

Data processing & features

  • 31.8M transactions processed with PySpark
  • Missing values, cold-start users / items
  • Context: month, day of week, recency
  • Popularity over 7 / 28 days / all time
  • Vocabularies for the embeddings
WEEK 2

Two-tower model

  • Query tower: customer ID, club, news, age, purchase stats, context
  • Candidate tower: article ID, type, colour, department, garment, popularity
  • In-batch negative sampling + logQ correction
  • Recall@K, NDCG@K, MAP@12 vs baseline
WEEK 3

Serving & feature store

  • Article vectors and tower weights exported
  • Redis: user features, item vectors, fallback
  • FAISS HNSW approximate nearest neighbours
  • Recall of ANN vs exact search measured
WEEK 4

API, pipelines & load test

  • FastAPI microservice + this web UI
  • Airflow: weekly retraining, daily embedding refresh
  • Concurrent stress test (p50 / p95 / p99)
  • Docker Compose deployment
